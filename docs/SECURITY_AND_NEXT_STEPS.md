# وضعیت امنیت و گام‌های بعدی

## API
مرجع مسیرها و محدودیت‌ها [API_CONTRACT.md](API_CONTRACT.md) و ساختار زنده [DATABASE_REFERENCE.md](DATABASE_REFERENCE.md) است. تمام دسترسی‌های خصوصی از Worker و نشست معتبر عبور می‌کنند.

## قواعد ایمنی
- هیچ اتصال مستقیم مرورگر به D1 وجود ندارد.
- ثبت فروش به Triggerهای D1 متکی است؛ API موجودی را دوباره کم یا بدهی را دوباره ایجاد نمی‌کند.
- تسویه بدهی و اصلاح موجودی تا ایجاد ledger قابل حسابرسی غیرفعال‌اند.
- Worker مستقل از GitHub Pages Deploy می‌شود.
- هیچ migration یا query تغییردهنده‌ای روی Production در این مرحله اجرا نشده است.

## پیش از انتشار
1. تست‌های Worker و build فرانت‌اند اجرا شوند.
2. Worker از Cloudflare Deploy شود و GET /health بررسی شود.
3. ورود، فهرست کالا، ایجاد/ویرایش کالا، ایجاد مشتری، ثبت فروش، ورود/خروج و گزارش آزمایش شوند.
4. تأیید شود موجودی و بدهی فقط یک بار توسط Triggerها تغییر می‌کنند.

## توسعه بعدی
- service token محدود برای ربات و کلاینت‌های غیرمرورگری.
- ledger پرداخت برای تسویه بدهی و اصلاح موجودی.
- sale_items و purchase_items برای عملیات چندقلمی.
- Audit trail برای تغییرات مشتری و کاربران.
