# فضای افزایشی مدیریت کالا و انبار

## هدف

این بخش با الهام از فهرست قابلیت‌های تعریف‌شده در README مخزن Inventory & Warehouse Management System ساخته شده است. مخزن مرجع در زمان بررسی فقط README داشت و فایل اجرایی HTML/CSS/JavaScript برای انتقال مستقیم در آن موجود نبود؛ بنابراین این پیاده‌سازی یک سازگارسازی مستقل با معماری واقعی `monitoring-shoma-site` است، نه کپی فایل‌های آن مخزن.

## فایل‌های افزوده‌شده

```text
src/
  modules/
    inventory-workspace/
      catalog.js       تعریف ماژول‌ها، گروه‌ها، وضعیت اتصال و توضیحات
      model.js         قالب‌بندی و توابع کمکی مستقل از UI
  pages/
    InventoryWorkspacePage.jsx   پوسته فضای مدیریت انبار و صفحات داخلی
    inventory-workspace.css      استایل مستقل و واکنش‌گرا
```

## اتصال به پنل

- یک ورودی جدید «مدیریت انبار پیشرفته» به منوی اصلی اضافه شده است.
- این ورودی از همان کنترل دسترسی فعلی پنل پیروی می‌کند؛ نقش employee همچنان فقط صفحه حضور و غیاب را می‌بیند.
- داخل صفحه، زیرمنوی مستقل و گروه‌بندی‌شده برای نمای کلی، کالاها، دسته‌بندی، برند، انبار، موقعیت، موجودی، گردش، اصلاح، انتقال، تأمین‌کننده، سفارش خرید، دریافت، سفارش مجدد، انبارگردانی، تقویم، تحلیل، گزارش و تنظیمات وجود دارد.
- صفحه فعلی «مدیریت اجناس» حذف یا جایگزین نشده است؛ صفحه محصولات جدید فقط به همان صفحه موجود پیوند می‌دهد.

## وضعیت اتصال

### متصل به API فعلی

- نمای کلی: `GET /api/v1/dashboard/summary`
- موجودی فقط‌خواندنی: `GET /api/v1/inventory`
- مدیریت محصول: از طریق صفحه موجود `ProductsPage.jsx` و APIهای فعلی ایجاد/ویرایش کالا

### اسکلت رابط کاربری، بدون عملیات نوشتنی

صفحات دسته‌بندی، برند، انبار، موقعیت، گردش، اصلاح، انتقال، تأمین‌کننده، سفارش خرید، دریافت، سفارش مجدد، انبارگردانی، تقویم، تحلیل، گزارش انبار و تنظیمات در این مرحله ساختار رابط و فهرست قابلیت‌ها دارند.

در قرارداد API و schema تأییدشده فعلی، endpoint یا جدول کافی برای این دامنه‌ها وجود ندارد. به همین دلیل:
- داده نمونه به‌عنوان داده واقعی نمایش داده نمی‌شود.
- دکمه ذخیره/حذف/ویرایش غیرواقعی اضافه نشده است.
- هیچ Migration یا تغییر D1 انجام نشده است.
- هیچ route یا repository موجود Worker بازنویسی نشده است.

## اصول حفظ عملکرد

- صفحه مدیریت اجناس، فروش، بدهی، مشتریان، حضور و غیاب و گزارش‌های فعلی دست‌نخورده باقی می‌مانند.
- هیچ فایل یا قابلیت قبلی حذف نشده است.
- صفحه جدید فقط برای نقش‌هایی نمایش داده می‌شود که منوی مدیریتی فعلی را می‌بینند.
- تمام داده‌های متصل از کلاینت API موجود عبور می‌کنند؛ مرورگر به D1 وصل نمی‌شود.
- طراحی زیرمنو، کارت‌ها، جدول موجودی و حالت‌های خالی/خطا برای موبایل و دسکتاپ واکنش‌گراست.

## ادامه توسعه

پیش از فعال‌سازی عملیات نوشتنی هر دامنه:
1. Schema واقعی D1 و مصرف‌کنندگان ربات فروشگاه با روش read-only بررسی شوند.
2. مدل داده و سازگاری backward مشخص شود.
3. Migration افزایشی و Audit مناسب طراحی شود.
4. endpointهای Worker با احراز هویت و مجوز سمت سرور اضافه شوند.
5. تست‌های SQLite/D1 ایزوله و آزمون‌های سازگاری اجرا شوند.
6. فقط پس از تأیید مستقل، درباره اجرای Migration روی دیتابیس میزبانی‌شده تصمیم گرفته شود.


## فاز اول اتصال داده‌های پایه

Migration افزایشی 0002 مدل دسته‌بندی، برند، انبار، موقعیت انبار و Audit اختصاصی را اضافه می‌کند. همچنین ستون‌های barcode، category_id، brand_id، min_stock و is_active را به محصولات اضافه می‌کند. این Migration هیچ داده یا جدول موجودی را حذف یا بازنویسی نمی‌کند.

چهار صفحه دسته‌بندی، برند، انبار و موقعیت به endpointهای فهرست/ایجاد/ویرایش متصل شده‌اند. دسترسی Worker به نشست معتبر و نقش owner/manager محدود است. ویرایش با updated_at به‌عنوان compare-and-swap و Audit اتمیک انجام می‌شود. حذف فیزیکی ارائه نشده است.

**مرز مهم:** موجودی چندانباره، گردش، اصلاح، انتقال، خرید و دریافت هنوز فعال نیستند. جدول inventory و Triggerهای فروش فعلی تا طراحی ledger سازگار بدون تغییر می‌مانند. Migration 0002 روی D1 میزبانی‌شده اجرا نشده است.
