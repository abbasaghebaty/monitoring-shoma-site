# فضای افزایشی مدیریت کالا و انبار

## هدف
این فضا ساختار آینده مدیریت انبار را در پنل نگه می‌دارد؛ اما وضعیت اتصال هر قابلیت باید با schema واقعی D1 هماهنگ باشد.

## فایل‌ها
- \`src/modules/inventory-workspace/catalog.js\`: فهرست و گروه‌بندی ماژول‌ها
- \`src/modules/inventory-workspace/model.js\`: قالب‌بندی و توابع مستقل از UI
- \`src/pages/InventoryWorkspacePage.jsx\`: پوسته و صفحات داخلی
- \`src/pages/inventory-workspace.css\`: استایل واکنش‌گرا

## بخش‌های متصل
- نمای کلی: GET /api/v1/dashboard/summary
- موجودی: GET /api/v1/inventory
- محصولات: صفحه اصلی ProductsPage و APIهای کالا
- قیمت‌ها: GET /api/v1/product-prices

## اسکلت‌های آینده
دسته‌بندی، برند، چندانبار، موقعیت، گردش، اصلاح، انتقال، تأمین‌کننده، سفارش خرید، دریافت، سفارش مجدد، انبارگردانی، تقویم، تحلیل و گزارش انبار در حال حاضر فقط ساختار رابط و نقشه توسعه هستند. جداول مربوطه در دیتابیس زنده وجود ندارند و هیچ درخواست خواندن/نوشتنی به جدول‌های غایب ارسال نمی‌شود.

## قواعد داده
- Migration 0002 در مخزن وجود دارد، اما روی D1 میزبانی‌شده اجرا نشده است.
- صفحه دسته‌بندی/برند/انبار/موقعیت فعلاً به API متصل نیست.
- موجودی زنده فقط خواندنی است؛ اصلاح مقدار بدون ledger و تاریخچه قابل حسابرسی غیرفعال می‌ماند.
- فروش Triggerهای خودش را برای کاهش موجودی اجرا می‌کند؛ هیچ مسیر دیگری نباید همان کاهش را تکرار کند.
- صفحه مدیریت اجناس موجود حذف یا جایگزین نشده است.

## ادامه توسعه
1. طراحی Migration افزایشی و سازگار با داده موجود
2. افزودن ledger تغییر موجودی و audit trail
3. تعریف مدل چندانباره و انتقال
4. اضافه‌کردن endpointها و مجوزهای مستقل
5. تست روی D1 ایزوله و سپس برنامه انتشار کنترل‌شده
