# Shoma Dashboard

پنل مدیریتی فروشگاه «شما»؛ رابط کاربری React + Vite با هدف انتشار روی github Pages و اتصال امن به Cloudflare Workers و D1.

## وضعیت فعلی

- رابط فارسی و راست‌چین، واکنش‌گرا برای موبایل و دسکتاپ
- داشبورد مدیریتی با کارت‌های شاخص، نمودار فروش و خلاصه موجودی
- منوی بخش‌های محصولات، فروش، انبار، خرید، مشتریان، مالی، گزارش‌ها، فاکتورها و تنظیمات
- جدول اولیه محصولات و وضعیت موجودی
- اعداد و نمودارهای فعلی صرفاً داده نمایشی هستند؛ هنوز به دیتابیس وصل نشده‌اند و نباید مبنای تصمیم مالی قرار گیرند.

## اجرا و ساخت

```bash
npm install
npm run dev
npm run build
```

خروجی انتشار در `dist` ساخته می‌شود و برای Cloudflare Pages مناسب است.

## معماری هدف

- Frontend: Cloudflare Pages
- API: Cloudflare Worker مستقل
- Database: دیتابیس D1 فعلی فروشگاه
- ارتباط مرورگر با API از طریق HTTPS و احراز هویت

## منبع داده فروشگاه

مخزن ربات: [monitoring_shoma](https://github.com/abbasaghebaty/monitoring_shoma)

بررسی کد مخزن ربات نشان می‌دهد که binding دیتابیس `DB` و دیتابیس `shop-manager` است. ماژول فروشگاه به جداولی از جمله `products`, `purchases`, `purchase_items`, `sales`, `sale_items`, `payments`, `debts`, `customers` و `shortages` متصل است.

**امنیت:** فرانت‌اند نباید مستقیماً به D1 وصل شود و نباید شناسه دیتابیس یا توکن محرمانه در کد مرورگر قرار بگیرد. تمام دسترسی‌ها باید از طریق Worker و endpointهای مجاز انجام شوند.

## قرارداد API پیشنهادی برای Worker

پیش از پیاده‌سازی نوشتن اطلاعات، ابتدا endpointهای فقط‌خواندنی را فراهم کن:

- `GET /api/v1/dashboard/summary` — آمار کلی و خلاصه داشبورد
- `GET /api/v1/reports/sales?from=YYYY-MM-DD&to=YYYY-MM-DD` — روند فروش در بازه
- `GET /api/v1/products` — فهرست و جست‌وجوی محصولات
- `GET /api/v1/inventory` — موجودی و هشدار کمبود
- `GET /api/v1/sales` — فهرست فروش‌ها و فاکتورها
- `GET /api/v1/purchases` — سوابق خرید
- `GET /api/v1/customers` — مشتریان و مانده حساب
- `GET /api/v1/finance/summary` — خلاصه مالی و هزینه‌ها، در صورت وجود جدول هزینه‌ها

پاسخ‌ها باید JSON پایدار، اعداد صحیح مبلغ بر حسب تومان، تاریخ استاندارد و خطاهای قابل‌فهم داشته باشند. احراز هویت و کنترل مجوز باید در Worker انجام شود. بعد از اتصال اولیه، عملیات نوشتن مانند ایجاد محصول، فروش و خرید را جداگانه و با اعتبارسنجی، کنترل موجودی و ثبت اتمیک اضافه می‌کنیم.

## نکات دیتابیس و حسابداری

- ساختار واقعی جداول و triggerهای D1 باید از migrationها و کد ربات بررسی شود؛ فایل schema محدود موجود در مخزن ربات به‌تنهایی schema کامل فروشگاه نیست.
- سود فعلی ربات «سود تقریبی» است و از اختلاف مبلغ فروش اقلام با قیمت خرید snapshot محاسبه می‌شود. این عدد سود خالص حسابداری نیست.
- پیش از نمایش سود ماهانه/سالانه باید هزینه‌ها، تخفیف‌ها، مرجوعی‌ها، اصلاح موجودی و زمان‌بندی ثبت تراکنش‌ها مشخص شوند.
- هیچ migration یا تغییری روی دیتابیس فعلی نباید صرفاً از سمت این فرانت‌اند اجرا شود.
